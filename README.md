# GamepadMapper（DQ10 手把映射，非 root）

## 為什麼給原始碼而不是 APK
這是完整可編譯的 Android Studio 專案，不是已編譯簽名的 APK。我這邊的環境沒有 Android SDK / Gradle 工具鏈也無法連到 Google Maven，無法在這裡編出可安裝的 APK。你用 Android Studio 開啟後可以直接 Run 到手機上安裝測試，或是 Build > Build APK(s) 匯出 apk 檔給別人裝。

## 建置步驟
1. 用 Android Studio 開啟 `GamepadMapper` 這個資料夾（File > Open）。
2. 等 Gradle sync 完成（需要網路抓 AGP 8.5.0 與相關依賴）。
3. 用 USB 接上 vivo X200 Pro（需先在手機的「關於本機」連點版本號開啟開發者模式，並開啟 USB 偵錯），按 Run 直接裝機。

## 使用步驟
1. 打開 App，點「1. 開啟無障礙服務」，在系統設定裡找到「手把映射 for DQ10」並開啟。
   - Origin OS 可能會提示「無障礙服務有安全風險」，這是正常的系統警告，確認開啟即可。
2. 點「2. 開啟懸浮窗權限」，允許此 App 顯示在其他應用程式上層。
3. 打開 DQ10，切到遊戲畫面。
4. 切回本 App，點「3. 進入按鍵位置設定模式」——這時 App 會退到背景，遊戲畫面上會出現紅色（按鍵）與藍色（搖桿中心）的可拖曳標記。
5. 把每個標記拖到遊戲對應的按鈕位置（例如把「A」標記拖到遊戲畫面上「確認」鍵的位置；把「搖桿中心」拖到遊戲內建虛擬搖桿的圓心）。
6. 按畫面下方「儲存位置」，設定就會生效，之後接上手把即可用實體按鍵/搖桿操作遊戲。

## 這次更新內容（測試模式強化，用來找背鍵）
測試模式原本只顯示「來源類型是手把」的按鍵事件，背鍵如果送出的來源類型不同，會在顯示之前就被過濾掉，看起來就像沒反應。現在改成：
1. **所有按鍵事件都顯示**，不管來源類型，並多列出 `scanCode`、來源（十六進位）、裝置名稱。`keyCode=0（UNKNOWN）` 的未知按鍵也會顯示，這時看 `scanCode` 就能分辨是哪顆。
2. 非手把來源的事件（例如音量鍵、返回鍵）**只顯示、不攔截**，測試期間手機實體按鍵仍可正常使用；手把來源的事件才會被消費。
3. **軸值區新增「其他軸」**：列出標準軸以外、數值不是 0 的軸（例如 `AXIS_GENERIC_1`～`16`），因為有些手把的額外按鍵是用類比軸而不是按鍵事件送出。
4. 軸值區底下顯示事件來源（十六進位）。

若這樣仍然完全沒有任何顯示，代表背鍵的訊號沒有送進 Android 輸入系統（可能由手把韌體內部處理，或當前模式下沒有輸出），App 層無法處理。

## 之前的更新內容（按鍵巨集功能、.gitignore）
1. **新增 `.gitignore`**：忽略 `.trashed-*`（Android 檔案管理 App 覆蓋檔案時產生的回收暫存檔，曾造成編譯出現重複類別錯誤），以及 `.gradle/`、`build/`、`.idea/` 等常見產物。注意 `.gitignore` 只對「尚未被 git 追蹤」的檔案有效，如果 `.trashed-*` 已經被 commit 進去，還是要用 `git rm` 移除一次。
2. **按鍵巨集**：每顆按鍵（含十字鍵）除了預設的「單擊」，可以切換成「巨集」，按一下就依序點擊多個位置。
   - 進入「⚙設定」後，**輕點（不是拖曳）**任一顆按鍵標記，畫面上方會出現該按鍵的編輯面板。
   - 面板上點「目前模式」按鈕切換單擊/巨集；切到巨集時會自動建立第一步（位置在原本的單擊位置）。
   - 每一步在畫面上是一顆橘色標記（例如 `Y1`、`Y2`…），拖到要點擊的位置；按「＋新增步驟」增加，最多 20 步。
   - 每一步之後的等待時間用 `-100 / -10 / +10 / +100` 按鈕調整（這層懸浮視窗叫不出鍵盤，所以不用輸入數字）。最後一步後面沒有下一步，所以沒有等待時間設定。
   - 實際執行時，每步間隔 = 點擊本身約 50ms + 你設定的等待時間；巨集跑到一半時，同一顆按鍵再按會被忽略。
   - 切回單擊模式時，巨集步驟會保留，下次切回巨集不用重設；把步驟全刪光則自動回到單擊。
   - 「還原預設」現在也會清除所有巨集（回到全部單擊），一樣要按「儲存位置」才會真正寫入。
   - 已知限制：巨集的每一步都是獨立的點擊手勢，如果同時正在推搖桿，搖桿的拖曳可能會被打斷（跟一般按鍵的既有限制相同）。

## 之前的更新內容（十字鍵HAT、狀態還原、L2/R2改單點、座標偏移修正嘗試）
1. **測試模式離開後會還原搖桿狀態**：跟設定模式一樣，進測試模式前會記住搖桿原本的開關，離開後還原，不再一律關閉。
2. **十字鍵改用 HAT_X/HAT_Y 軸偵測**：這隻手把的十字鍵不是按鍵事件，而是 HAT 軸（-1/0/1）。現在用「邊緣觸發」偵測方向變化，觸發對應十字鍵座標的一次點擊（沿用原本上/下/左/右四個標記的位置）。
3. **L2/R2 改回單點點擊**，取消滑動手勢，設定畫面標記也改回一般紅色。
4. **左右搖桿同時推的自我修復機制**：偵測 `dispatchGesture` 是否被系統拒絕，被拒絕時重置兩根搖桿的延續狀態，避免手勢鏈永久卡死。**此項是否真正解決仍需實測確認。**
5. **座標偏移修正嘗試**：所有懸浮視窗加入 `FLAG_LAYOUT_IN_SCREEN`、`FLAG_LAYOUT_NO_LIMITS` 與 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS`，讓視窗座標盡量對齊原始物理螢幕。**此為假設性修正，需實測確認偏移是否消失。**

## 之前的更新內容（右搖桿支援、還原預設、按鍵縮寫、MODE鍵）
1. **右搖桿支援**：確認你的手把右搖桿是 `AXIS_Z`（左右）、`AXIS_RZ`（上下），已比照左搖桿加上映射邏輯。設定模式裡新增一顆青色「右搖桿中心」標記，跟藍色的左搖桿中心一樣，拖到遊戲畫面上右搖桿慣用的區域即可。
   - **技術細節**：左右搖桿如果同時操作，會合併進「同一次」手勢呼叫送出去，因為 Android 一次 `dispatchGesture` 代表當下所有手指的狀態，分開呼叫的話後面那次會直接打斷前一個，這樣才能兩根搖桿同時使用不互相打架。
2. **設定模式新增「還原預設」按鈕**：跟「儲存位置」並排在畫面下方，點下去會把所有標記（含左右搖桿中心）重新排回預設的比例位置，方便設定亂了想重來；要注意這只是重排畫面顯示，仍要再按一次「儲存位置」才會真正寫入。
3. **START/SELECT 縮寫成 ST/SL**，標記文字更短，比較不擋畫面。
4. **新增 MODE 鍵支援**（`KEYCODE_BUTTON_MODE`，代碼 110），標記縮寫為 MD，跟其他一般按鍵一樣是單純點擊映射。

## 之前的更新內容（搖桿節流 + 測試模式擴充）
1. **修正搖桿放開後還會「補完」剛才動作的問題**：原因是搖桿的類比訊號觸發頻率遠高於每段延續手勢的播放時間，快速畫一圈會瞬間塞入十幾段動作到佇列，系統得照順序全部播完才會輪到放開那一下。現在限制了送出頻率，跟每段手勢的播放時間對齊，放開會立即生效、不再被佇列卡住。
2. **測試模式擴充顯示所有可能用到的軸**：新增顯示 `AXIS_Z`、`AXIS_RZ`、`AXIS_RX`、`AXIS_RY`（右搖桿可能用到）、`AXIS_LTRIGGER`、`AXIS_RTRIGGER`、`AXIS_BRAKE`、`AXIS_GAS`（L2/R2 扳機可能用到）。之前右搖桿「完全沒反應」，其實是測試模式根本沒去讀這些軸，不是系統或手把的問題。麻煩開測試模式後推右搖桿、壓 L2/R2，把有變化的那幾個數值截圖回報，我再照實際軸代碼把右搖桿映射、扳機判斷寫進去。
3. **L2/R2 長按無效的原因（尚未修正，需要你先決定方向）**：很可能是因為 L2/R2 在你的手把上是「類比扳機」，Android 會在扳機值跨過門檻時自動合成一個瞬間的 DOWN+UP，而不是持續的按住狀態，導致我們收不到「還按著」的訊息。若要繼續用 L2/R2，需要改成直接讀取扳機的類比軸值（見上一點的測試結果）來判斷按住/放開，這個會在你回報軸值測試結果後一併處理；若不想等，也可以先把這兩個功能改綁到 L1/R1（一般數位按鍵，行為穩定）。

## 之前的更新內容（關鍵 Bug 修正：手勢完全無效的根本原因）
無障礙服務要呼叫 `dispatchGesture()`（我們用來模擬點擊/滑動的核心方法），除了基本的無障礙服務權限之外，**還需要在服務設定檔裡額外聲明 `android:canPerformGestures="true"`**，這是收訊號（`onKeyEvent`/`onGenericMotionEvent`）完全不需要的一個獨立權限。這次修正前完全漏掉這個屬性，導致 `dispatchGesture()` 呼叫全部被系統靜默擋下（不會報錯、就是沒反應），這就是「測試模式看得到按鍵訊號，但實際點擊/滑動完全沒用，連在桌面上都一樣」的根本原因，跟 DQ10 這款遊戲本身無關。
已在 `app/src/main/res/xml/accessibility_service_config.xml` 加入這個屬性。

**更新後請務必到 設定 → 無障礙功能，把「手把映射 for DQ10」這個服務關掉再重新打開一次**，確保系統重新讀取新的服務能力宣告。

## 之前的更新內容（Bug 修正）
1. **修正設定位置沒有正確載入的問題**：之前每次打開設定模式，標記都只會顯示「螢幕比例算出來的預設位置」，完全沒去讀之前存過的座標，看起來就像「存檔後又還原了」，其實是介面沒把已存資料讀進來顯示。現在打開設定模式時，已經存過座標的按鍵會直接顯示在上次存的位置。
2. **修正搖桿狀態離開設定模式後沒有還原的問題**：之前進入設定模式一定會關掉搖桿收訊，離開後也維持關閉；現在會記住進設定模式之前的開關狀態，離開後自動還原回原本的狀態。

## 之前的更新內容（架構調整）
之前設定模式／測試模式是「在 GamepadMapper 這個 App 裡按按鈕，再想辦法切回遊戲」，但 `moveTaskToBack` 這個做法不可靠，常常跳回桌面而不是跳回遊戲。**這次改成三顆常駐的懸浮小按鈕，直接貼在螢幕上（不管你在哪個 App 都看得到），完全不需要切換 App**：

- **🎮搖桿**：開關搖桿類比收訊。開啟時遊戲視窗會失去 focus（前面討論過的既有取捨），用完記得點一下關掉。
- **⚙設定**：開關按鍵位置設定模式，畫面上會疊出可拖曳的標記（紅色=一般按鍵、紫色=L2/R2 滑動按鍵、藍色=搖桿中心），拖到遊戲對應位置後按「儲存位置」即可。
- **🔍測試**：開關按鍵測試模式，按手把上任何按鍵或推動搖桿/十字鍵，畫面下方會即時顯示對應的 `keyCode`/軸值，不會誤觸遊戲。

三顆按鈕都可以按住拖曳到畫面上不擋視線的位置（例如螢幕邊緣）。**正確流程是：先在 DQ10 裡（不是在 GamepadMapper 這個 App 裡）直接點懸浮按鈕操作**，全程不用切換 App。

其餘更新：
1. **固定簽名憑證**：新增 `app/debug.keystore`，並在 `app/build.gradle` 指定 debug 簽名固定用這把 key，之後雲端建置出來的 APK 才能用覆蓋安裝更新（**這次更新仍要先解除安裝舊版一次**，因為舊版簽名不同；之後就正常了）。
2. **設定模式支援橫向**：標記的預設位置改用「當下螢幕寬高的百分比」計算，橫向遊戲進入設定模式也會正確分佈。
3. **新增 L1 / R1 / L2 / R2**：L1、R1 是一般點擊；L2、R2 固定做成滑動手勢，L2 放開會模擬向左滑，R2 模擬向右滑。

## 已知限制（務必先實測，這是純類比映射方案的既有取捨）
- **搖桿類比訊號需要懸浮視窗拿 window focus**，這會讓 DQ10 遊戲視窗失去 focus。多數手機遊戲對此不敏感，但少數用 Unity 且沒開 `runInBackground` 的遊戲可能出現卡頓或提示。這點需要你實際測試 DQ10 的反應，如果有問題，可以再討論用 Shizuku 方案繞開（見之前的討論）。
- 搖桿移動是用「延續手勢（continued gesture）」模擬手指拖曳，對應到 DQ10 內建的觸控虛擬搖桿；如果 DQ10 沒有內建觸控虛擬搖桿（例如角色移動是靠點擊地圖），這個映射邏輯不適用，需要另外設計。
- 目前沒有處理「搖桿拖曳」與「按鍵點擊」同時發生時的多點觸控合併，兩者同時操作可能其中一個動作會被打斷，這對回合制/場景移動的 DQ10 影響應該不大，但仍建議實測。
- 按鍵座標是絕對座標（螢幕像素位置），如果 DQ10 在不同解析度/分割畫面下 UI 位置改變，映射座標需要重新設定。
- 目前只支援 DPAD 上下左右、A/B/X/Y、START/SELECT 共 10 個按鍵 + 1 個搖桿，之後要加其他按鍵（例如 L1/R1）可以在 `GamepadMapperService.SUPPORTED_KEYCODES` 與 `ConfigOverlay` 裡新增對應的 `addMarker` 呼叫。

## 檔案說明
- `MainActivity.java`：權限引導 + 進入設定模式的入口
- `GamepadMapperService.java`：核心邏輯，攔截手把按鍵/搖桿，轉成觸控手勢
- `ConfigOverlay.java`：設定模式下可拖曳的標記 UI
- `MappingStore.java`：座標設定的 SharedPreferences 讀寫
